# X-ray 검사장비 이물질 검출

KAMP(K-인공지능 제조 플랫폼) **X-ray 검사장비 AI 데이터셋**으로 완제품 X선 영상의 이물질(`defect`)을 검출하는 프로젝트입니다.

Windows 11에서만 검증했습니다. GPU는 NVIDIA RTX 4050 Laptop 6GB였고, GPU가 없으면 `--device cpu`로 돌릴 수 있지만 매우 느립니다.

```bash
pip install torch==2.6.0 torchvision==0.21.0                                                      # CPU 전용

pip install -r requirements.txt

python -c "import torch; print(torch.__version__, 'CUDA:', torch.cuda.is_available())"
```
`requirements.txt`는 검증한 버전으로 고정되어 있고 노트북용 jupyter도 포함합니다. 새 환경에서 처음부터 설치해 본 적은 없고 작성 당시 환경과의 일치만 확인했습니다.

## 전처리와 모델링에서 알아야 할 것 (이전 시도에서 겪은 함정)
이전 시도에서 실제로 확인한 사실입니다. 근거는 지운 문서(`git show d151bfa:docs/dataset.md`, `docs/troubleshooting.md`)에 있습니다.

1. **이미지에 장비가 그린 색 박스(표시)가 이미 찍혀 있습니다.** 확인한 라벨된 500장 모두에 1~3개씩 있고, 정답 박스 중심의 99.8%가 이 표시 안에 있습니다. 표시를 지우지 않고 학습하면 모델이 결함이 아니라 표시를 보고 맞힙니다. 실제로 표시가 있는 이미지로 학습한 모델은, 표시를 지운 입력에서 **하나도 찾지 못했습니다**(TP 0).
2. **표시를 지우는 방식이 중요합니다.** 주변 픽셀로 메우기만 하면(OpenCV `inpaint`) 메운 자리가 주변보다 매끈해서 윤곽이 남고, 질감 통계 하나로 윤곽 자리를 AUC 0.73~0.75로 구분할 수 있었습니다. **Navier-Stokes 보간 + 주변과 같은 세기의 노이즈(x0.75)**를 더하면 AUC 0.57로 내려갔습니다. 표시를 지운 자리에 모델이 반응하는지 확인하는 검증(결함이 없는 자리에 가짜 표시를 그렸다 지워 보기)에서는 반응이 없었습니다.
3. **라벨된 이미지는 400장이 아니라 500장입니다.** 라벨 txt는 `라벨링 6종 세트/labels/`에 500개가 있고, 이미지는 400장이 `images 400/`에, 나머지 100장은 원본 bmp 폴더에 같은 이름으로 따로 있습니다.
4. **파일명 앞의 001/002는 호기(장비) 번호가 아닙니다.** 002는 1호기와 2호기가 섞여 있고 001이 3호기입니다. 호기는 원본 폴더 위치로만 알 수 있고(내용 해시 대조), 호기마다 해상도가 다릅니다(1호기 352x332, 2호기 316x332, 3호기 576x444). 라벨 500장은 1호기 156 / 2호기 177 / 3호기 167장입니다.
5. **원본에 정상(결함 없음) 이미지가 없습니다.** 모두 장비가 NG로 판정한 이미지라 이미지 단위 오검출(FP)은 따로 정상 데이터 없이는 잴 수 없습니다. 원본 bmp 2,809장 중 277장은 같은 호기 안의 동일 파일 중복이라 고유 이미지는 2,532장입니다.
6. **분할은 호기별 층화 + 연속 촬영 묶음 단위로 해야 합니다.** 연속 촬영본(촬영 간격 60초 이내)은 서로 매우 닮아서 train과 test에 갈라 넣으면 평가가 부풀려집니다. 이전에 8:1:1로 train 400 / val 51 / test 49장으로 나눴고 분할 간 겹침과 60초 이내 인접 쌍은 없었습니다.
7. **평가는 신뢰도 임계값을 val에서 정해 고정하고 test는 한 번만 봅니다.** YOLOv3 `test.py`의 P/R/F1은 신뢰도 0.1 한 지점 값이라 같은 가중치도 평가 해상도에 따라 F1이 0.70~0.92로 흔들렸습니다. 두 모델 모두 신뢰도가 낮게 나와서 신뢰도 0.5 이상에서는 아무것도 못 찾았습니다.
8. **한글 경로와 운영 함정**: `cv2.imread`가 한글 경로를 못 읽습니다(`cv2.imdecode(np.fromfile(...))` 필요). 학습 결과가 공용 `last.pt`를 덮어써서 원본 가중치를 잃은 적이 있습니다. 프로젝트가 OneDrive 폴더 안이면 상태 파일 교체가 거부되어(WinError 5) 기록 프로세스가 죽은 적이 있습니다. 긴 학습 중에는 PC 절전을 꺼야 합니다.

## 이전 시도의 참고값 (삭제된 결과, 새 결과와 직접 비교하지 않음)
표시를 지운 n500 데이터, COCO 사전학습에서 시작, 100 epoch, 신뢰도 임계값은 val에서 정함, IoU 0.5, 640px 기준입니다.

| 모델 | 임계값 | test F1 | TP / FP / FN | test 이미지 |
|---|---|---|---|---|
| YOLOv3-tiny | 0.05 | 0.940 | 109 / 7 / 7 | 49장 (정답 116개) |
| YOLOv3-SPP | 0.07 | 0.966 | 112 / 4 / 4 | 49장 |

- 두 모델의 test F1 차이는 +0.026이고 이미지 단위 부트스트랩 95% 구간이 +0.003 ~ +0.054로 0에 가까워 **우열을 확정하지 못했습니다.** val·test가 49~51장이고 학습 시드가 하나뿐이었습니다.
- 학습 시간은 tiny 약 10분, SPP 약 50분(RTX 4050 6GB, SPP는 batch 3).
- 이 결과 파일은 지웠고 새 데이터와 코드로 다시 만들어야 합니다.
