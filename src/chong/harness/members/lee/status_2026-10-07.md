- ONNX 는 `nms=True, conf=0.001, iou=0.7, max_det=50` 으로 내보내 PyTorch 와 같은 검출 경로를 유지했다. 검출률이 소수점까지 같다.
- 원본 데이터로는 경량화 손해가 보이지 않는다. 손해는 아래 합성에서만 드러난다.
- 가중치 크기 축(INT8, 모델 폭 축소)은 하지 않았다. YOLO26n 은 이미 2.5M 파라미터·5.4MB 로 가장 작고, 다른 PC 의 INT8 실험(06)은 파일 1/4 이 됐지만 느려지고 F1 이 떨어져 뺐다.
- CPU 속도 주의: P코어·E코어가 섞인 노트북에서 코어 배정에 따라 3~4배 흔들린다. 위 값은 P코어 고정으로 쟀고, 공장 PC 수치 보장이 아니다.

## 3. 합성: "어떤 조건에서 놓치나" 를 재는 실험 (학습에는 안 넣음)

### 3-1. 지운 합성 (synth_normal): 모델이 점을 보나, 자리를 외우나
val 350장에서 이물질 자리를 옆 조각 복사로 덮어 "정상" 을 만들고 예측.
- 합성 정상 오경보 0.3% (1/350), 지운 자리 검출 0, 대조(임의 자리 덮기) 0%.
- **모델은 자리가 아니라 점 자체를 본다.** (10-06 아침의 "76% 자리 외우기" 는 메우기 버그였고, 팀 저장소에도 이번 PR 로 정정했다.)

### 3-2. 넣은 합성, 띠 안 5,930곳 (09_synth_band_lightweight)
실제 이물질이 늘 있는 어두운 띠 안에만 점 신호(실제 라벨에서 추출한 6~8px 잔차)를 한 곳씩 넣었다. 배경 val 33장, 진하기 1.0 / 0.7 / 0.5 / 0.35 / 0.25. 검출 = 넣은 뒤 확신도 0.42 이상이고 넣기 전에는 미만. 넣기 전 검출은 전 설정에서 0.

| 설정 | 진하기 1.0 (실제와 같음) | 0.7 | 0.5 | 0.35 | 0.25 |
|---|---|---|---|---|---|
| GPU 1024 | 100% | 88% | 48% | 19% | 3% |
| GPU 640 추론 | 94% | 65% | 43% | 19% | 2% |
| 640 학습 (lee_003) | 93% | 70% | 44% | 18% | 2% |
| ONNX CPU (1·4스레드) | 각각 위 640 값과 동일 | | | | |

호기별 (진하기 0.7 / 0.5):

| 설정 | 1호기 | 2호기 | 3호기 |
|---|---|---|---|
| GPU 1024 | 99% / 98% | 96% / 74% | 80% / 18% |
| GPU 640 추론 | 100% / 99% | 91% / 78% | 40% / 6% |
| 640 학습 | 100% / 98% | 98% / 80% | 46% / 7% |

- **실제와 같은 진하기면 띠 안 어디든 잡는다.** 띠 안 위치별 검출률 49~52% 로 차이 없음. 실제 이물질은 늘 왼쪽 끝에만 있는데도 그렇다.
- **미탐 경계는 진하기 0.7~0.5 사이.** 실제보다 30% 옅으면 10개 중 1개, 반이면 절반을 놓친다.
- **3호기가 가장 약하다.** 배경 잡음이 거칠어 옅은 점이 묻힌다.
- **640 축소의 손해는 3호기에 몰린다.** 진하기 0.7 에서 80% → 40%. 1·2호기는 그대로다. 3호기 사진이 576px 로 가장 커서 축소 비율이 가장 크다. 640 으로 학습해도(46%) 많이 못 만회한다.
- 이 수치는 실제 장비 미탐률이 아니다. 데이터에 장비가 놓친 사진이 없으므로, 신호를 옅게 만들어 "어디까지 보이나" 를 간접 추정한 것이다. 이런 불량이 실제로 나오는지는 모른다. 그래서 학습 강화는 하지 않고, 조건 설명으로만 쓴다.

### 3-3. 그 전 합성 (다른 PC, 05_probe_map_val)
762곳 중 72% 가 밝은 제품 몸통에 있었다. 실제 이물질은 전부 어두운 띠 안이라 데이터에 없는 조건이었고, 그래서 검출률 45% 가 나왔다. 09 는 이 교훈으로 띠 안에만 넣은 것이다. 합성은 "어떻게 넣느냐" 만큼 "어디에 넣느냐" 가 중요하다.

## 4. 결론 문장 (보고서용 뼈대)
1. 기준 데이터로 학습하면 YOLO26n 1024 는 val·test 이물질 중심을 전부 잡는다 (F1 0.99, 미탐 0). 팀의 다른 모델 셋도 같다. 천장은 데이터다.
2. 모델은 자리를 외운 게 아니라 점을 본다 (지운 합성 오경보 0.3%, 띠 안 어디든 같은 검출률).
3. 조건을 더해 보면: 점이 실제보다 30% 옅어지면 10개 중 1개, 반이면 절반을 놓친다. 3호기가 가장 약하다.
4. 경량화: 입력 640 + ONNX CPU 로 1초 27장(4스레드)이 되고 원본 성능은 그대로다. 손해는 3호기의 옅은 점에서만 나므로, 현장 배포는 ONNX 640 CPU 로 하되 3호기는 1024 유지를 권장한다.
5. 다음 데이터 수집 포인트: 장비가 놓친(또는 옅은) 실제 불량 사진. 그것이 있어야 3번을 검증하고 학습에 넣을 근거가 생긴다.
