Python 실행 파일을 직접 지정하려면 PowerShell에서 다음과 같이 실행합니다.


## 지금까지의 결론

- YOLO26n, 입력 1024, 40 epochs, batch 8, seed 42로 다시 학습했습니다.
- 원본 val의 이물 중심 606개를 모두 찾았습니다. 기준 IoU F1은 99.01%입니다.
- 640 GPU FP32는 원본 F1이 99.34%지만 합성 위치 검출은 341→292/762로 줄었습니다. 같은 위치 기준 119개를 잃고 70개를 얻었습니다.
- CPU ONNX FP32/640은 배포 기준 후보입니다. 기존 PC의 독립 실행 p95는 1 thread 57.53 ms, 4 threads 33.67 ms입니다.
- 제품 주변을 자르는 ROI 후보는 CPU 합성 검출 293→327/762, p95 57.53→58.06 ms였지만 원본 F1은 99.34→99.01%였습니다. 기존 합성 성공 79개를 잃고 113개를 얻어, 일괄 개선으로 해석하지 않습니다.
- 이번 INT8 후보는 작아졌지만 느려져 채택하지 않았습니다. 배포 구성은 단일 모델·한 번의 추론입니다.

## 다음 작업 순서

1. **사용자가 합성 품질부터 검토합니다.** `runs/chong/05_probe_map_val/qa.html`에서 6개 이물 출처의 원본/추정 배경/분리 잔차/삽입 전후를 확인합니다. 자동/이전 육안 검수만으로 실제 이물 신호의 정확한 분리를 보증하지 않습니다.
2. 분리가 부정확하면 합성 방법을 수정한 **새 버전·새 실험 폴더**를 만들고 지도와 설정 비교를 다시 합니다. 현재 결과를 새 방법의 결과로 덮어쓰지 않습니다. 76% 잔존 검출을 위치 암기의 증거로 되살리지 않습니다.
3. 분리가 납득되면 ROI의 **얻은 113곳/잃은 79곳**을 살펴 개선과 퇴보 원인을 비교합니다. 원본 F1과 위치별 손실을 함께 보고 배포 설정을 결정합니다.
4. 추가 학습이 필요하다고 판단할 때만 train 출처 합성을 사용하고, 같은 조건의 비증강 대조 학습과 비교합니다. val 템플릿/위치를 학습에 넣지 않습니다. 무조건 더 어렵게 만든 데이터로 성능 저하를 유도하지 않습니다.
5. 원본 점수 → 경량화 시 위치별 손실 → 단일 추론 개선 후보 → 필요한 CPU 시간/메모리 순서로 대회 설명을 정리합니다. 최종 후보와 임계값이 정해진 뒤에만 팀 절차로 test를 평가합니다.

이물 재질은 확인되지 않아 '금속구'라고 단정하지 않습니다. 합성은 가공된 회색조 영상의 배경 차이를 이동한 실험이며 실제 장비 미탐률, 정상 제품 오경보율, 물리적 최소 검출 크기를 입증하지 않습니다. ROI는 val 결과를 보고 추가한 탐색 후보입니다.
