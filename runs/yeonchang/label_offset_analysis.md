# 미검출(FN) 원인 분석: 라벨 박스 위치·크기 vs 실제 결함 점

작성: 정연창 (2026-10-07). 대상 모델: `02_rtdetrl_img640_e30`(RT-DETR-l), `03_dfinen_img640_e50`(D-FINE-N). 데이터: 확정 v2.

## 요약
- IoU 0.5 기준 test 미검출 중 **공식 라벨 7건은 모두 모델이 결함 점의 중심을 1px 이내로 찾은 경우**다. 라벨 쪽 원인으로 IoU가 0.43~0.50에 머물렀다.
  - **라벨이 점에서 치우침 (2건)**: 라벨 중심이 실제 점에서 2.7~3.2px 벗어나 있음. 라벨을 크기 그대로 점 중심으로 옮기면 IoU 0.53~0.67로 TP가 된다.
  - **라벨 크기가 다름 (5건)**: 라벨은 점 위에 맞게 있으나 크기(5~7px 또는 14~15px)가 모델 박스(약 10px)와 달라, 라벨이 예측 박스 안에 들어가거나 그 반대가 되어 IoU가 면적 비율로 정해진다.
- 모델은 결함 크기와 무관하게 **약 10px(3호기 약 13px) 박스를 그린다.** 학습 라벨의 75%(팀 라벨)가 클릭 중심의 고정 크기 네모라 크기를 배울 정보가 없다.
- **실제로 놓친 결함은 1건**(팀 라벨, 저대비)이고 RT-DETR-l만 놓쳤다. D-FINE-N은 검출했다.
- 전체 라벨 4,494개로 보면 공식 라벨도 대부분 점 위에 있다(중앙값 0.99px). 다만 **2px 이상 치우친 박스가 6.9%로 팀 라벨(1.0%)보다 많고, 3호기는 16.3%**다.

## 방법
- **실제 점 중심**: 라벨 박스+4px 안에서 black top-hat(7px 원형)으로 작은 어두운 점만 남기고, 최대값의 절반 이상인 연결 영역의 밝기 가중 중심. 4,494개 박스 모두에서 점을 찾았다(자동 검출, 수작업 확인은 아래 사례 이미지만).
- **치우침** = 라벨 박스 중심 − 실제 점 중심 (px, 원본 해상도).
- **실패 사례**: 각 모델의 test 미검출(val에서 정한 임계값, IoU 0.5)마다 가장 가까운 임계값 이상 예측을 찾아 예측 중심↔점, 라벨 중심↔점 거리, IoU, 라벨을 점 중심으로 옮겼을 때의 IoU를 계산.
- 모델은 다시 돌리지 않았다. 저장된 예측(`preds_test.json`)만 읽는다. 라벨 품질을 보는 분석이라 test를 튜닝에 쓰지 않는다.

## 3. 해석과 주의
- 공식 라벨 기준 IoU 오류는 "결함을 못 찾음"이 아니라 **라벨과 모델 박스의 위치·크기 정의 차이**다. 중심 거리 3px 기준 test F1은 RT-DETR-l 0.9985(FP 1 / FN 1), D-FINE-N 0.9977(FP 2 / FN 1). 각 실험 폴더의 `eval_center_sensitivity.json`.
  - D-FINE-N의 중심 기준 FN 1건 `001_20200625_043337(3)` #0(공식)은 신뢰도 0.784 예측이 라벨 중심에서 3.14px라 3px 기준을 0.14px 넘긴 경우다. IoU 0.5 기준으로는 TP이고 실제 미검출이 아니다.
- **test 라벨을 고쳐 다시 채점하지 않는다.** `data/`는 공유 영역이고, 결과를 본 뒤 정답을 바꾸면 평가가 오염된다. 공식 지표(IoU 0.5)는 그대로 보고하고, 이 분석은 라벨 품질 한계와 보조 지표의 근거로 쓴다.
- 점 위치는 자동 검출이다. 사례 확대 이미지(아래)로 일부만 눈으로 확인했다.
- 모델이 크기를 배우지 못하는 것은 라벨 방식(팀 라벨 고정 크기)의 한계다. 크기 추정이 필요하면 공식 라벨만으로 크기를 학습하거나 크기 회귀를 따로 평가해야 한다.
