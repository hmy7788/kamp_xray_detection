# 데이터셋 정리

X-ray 검사장비 AI 데이터셋의 로컬 보유 현황입니다. 아래 수치는 파일을 직접 세어 확인한 값입니다. (기준일 2026-09-30)

## 요약

| 항목 | 내용 |
|---|---|
| 과제 | X선 영상 기반 완제품 이물질 탐지 |
| 클래스 | 1개 (`defect`, id 0) |
| 라벨 포맷 | YOLO darknet (`class x_center y_center w h`, 0~1 정규화), 이미지와 같은 이름의 `.txt` |
| 원본 이미지 | `.bmp`, 장비 3대(1~3호기)의 NG 이미지 |
| 학습용 이미지 | 확장자만 `.jpg`이고 **실제 내용은 BMP**(원본과 바이트 동일, 400장 모두 MD5 일치 확인) |

## 1. 원본 이미지 (`test1/yolov3/X선이물검출기(06.23_09.22)` → `X선이물검출기`)

- 원본 폴더는 호기별로 `SN..._NgImage` 하위 폴더에 나뉘어 있고, 재정리 셀이 NgImage 파일만 호기별로 복사한 것이 `X선이물검출기/`입니다.
- 호기별 재정리 결과: **1호기 943 / 2호기 805 / 3호기 784 = 2,532장**
- 원본 폴더 전체 bmp는 **2,809장**(호기별 1호기 1,031 / 2호기 920 / 3호기 858, `SN..._NgImage` 폴더 131개)입니다. 모두 장비가 NG로 판정한 이미지입니다(정상 이미지 폴더는 없음).
- 재정리 결과가 2,532장으로 적은 이유는 **같은 호기 안에서 동일한 파일이 두 NgImage 폴더에 중복 저장**되어 있기 때문입니다(확인 완료). 파일명이 겹치는 280건 중 277건은 내용(MD5)이 완전히 같은 중복이고, 나머지 3건은 1호기와 2호기에서 파일명만 같고 내용이 다른 충돌입니다. 고유 이미지는 2,809 - 277 = **2,532장**입니다.
- 촬영 기간: 2020-06-22 ~ 2020-09-22 (46일)
- **파일명 접두는 호기 번호가 아닙니다.** 접두 `002` = 1호기와 2호기(두 장비가 같은 접두를 씀), 접두 `001` = 3호기입니다. 파일명 규칙: `{접두}_{YYYYMMDD}_{HHMMSS}({숫자}).bmp`. 호기는 폴더 이름(`N호기(2020.09.22)`)으로만 알 수 있어 `data/manifest.csv`에 정리했습니다.
- 이미지 크기는 **호기별로 고정**입니다: 1호기 352x332(샘플에서 316x332, 412x332도 관찰), 2호기 316x332, 3호기 576x444(파일 크기가 다른 호기의 약 2.5배).

## 2. 라벨링된 데이터

| 위치 | 이미지 | 라벨 파일 | bbox 수 | 비고 |
|---|---|---|---|---|
| `test1/yolov3/images`, `labels` | 15 | 15 | 23 | 실습 기본 세트 (train 12 / test 3) |
| `라벨링 6종 세트/images 15` | 15 | 15 | 35 | |
| `images 50` | 50 | 50 | 118 | |
| `images 100` | 100 | 100 | 234 | |
| `images 200` | 200 | 200 | 466 | |
| `images 300` | 300 | 300 | 765 | |
| `images 400` | 400 | 400 | 1,047 | |
| `라벨링 6종 세트/labels` | - | **500** | - | 6개 세트 공용 라벨 폴더 |

- 모든 세트에서 이미지와 라벨이 1:1로 대응하며, 빈 라벨은 없습니다. 모든 bbox가 클래스 0입니다.
- 이미지 1장당 평균 bbox 약 2.2~2.6개 (한 이미지에 결함이 여러 개인 경우가 흔함).
- 공용 `labels/`에는 라벨 500개가 있는데 가장 큰 세트는 400장이라, **100개는 어떤 세트에서도 쓰이지 않습니다**(500번째까지 쓰는 세트는 없음).
- 이 세트들은 `실습별 가중치파일/last{15,50,100,200,300,400}.pt`와 짝입니다.

### 서브셋 포함 관계 (확인 완료)

세트들은 **서로 독립된 데이터가 아니라 중첩**되어 있습니다. 파일명과 내용(MD5) 두 기준으로 비교한 결과가 같았습니다.

`n015 ⊂ n050 ⊂ n100 ⊂ n200 ⊂ n300 ⊂ n400`

- 6개 세트의 이미지 합계는 1,065장이지만 중복을 제거하면 **고유 이미지는 400장**(= `n400`)입니다.
- 따라서 **라벨이 있는 고유 이미지는 400장(bbox 1,047개)이 전부**입니다. 나머지 고유 이미지 약 2,132장(2,532 - 400)은 라벨이 없습니다. 라벨 400장은 원본과 내용이 모두 일치하며, 호기별로 **1호기 124 / 2호기 109 / 3호기 167장**입니다(3호기도 포함). 파일명 충돌 3건은 라벨 이미지에 해당하지 않아 라벨과 이미지의 대응은 모호하지 않습니다.
- 세트를 합쳐서 학습하면 새 데이터는 없고 작은 세트의 이미지만 최대 6번 중복되어 들어갑니다. 합칠 필요 없이 `n400`만 쓰면 됩니다.
- train/val 분할은 합치지 않은 단일 세트(`n400`)에서 해야 같은 이미지가 양쪽에 들어가는 누수를 막을 수 있습니다.
- 이미지 수별 비교(15→400장)는 서로 다른 데이터의 비교가 아니라 "같은 400장 중 앞의 일부만 쓴 경우"의 비교입니다.

## 3. bbox 크기 (정규화 값)

| 세트 | 평균 w | 평균 h | 최소 w/h | 최대 w/h |
|---|---|---|---|---|
| test1/yolov3 (15장) | 0.013 | 0.018 | 0.005 / 0.014 | 0.019 / 0.024 |
| images 15 | 0.021 | 0.026 | 0.014 / 0.018 | 0.026 / 0.038 |
| images 100 | 0.022 | 0.029 | 0.010 / 0.018 | 0.036 / 0.047 |
| images 400 | 0.026 | 0.029 | 0.010 / 0.015 | 0.051 / 0.054 |

- 결함은 이미지 폭/높이의 **약 1~5%**밖에 안 되는 **매우 작은 객체**입니다 (352px 이미지 기준 대략 4~18px).
- 학습 해상도가 320~640이라 작은 결함의 미탐지(FN) 원인이 될 가능성이 큽니다. "AI 미탐지 조건 분석"에서 우선 확인할 후보입니다.

## 4. 라벨링 도구 폴더 (`OpenLabeling-master/main`)

- `input/`: 이미지 15장, `output/YOLO_darknet/`: 라벨 15개
- `output/PASCAL_VOC/`: XML **833개**, 이 중 X-ray는 35개뿐이고 나머지 798개(`people_walking_mp4_*` 795, `img_*` 3)는 도구 데모 파일입니다. 학습 데이터가 아닙니다.

## 5. 유의 사항

- 실습 기본 세트(15장)는 파일명 접두 001(3호기)과 002(1·2호기)를 모두 포함하지만 장수가 적어 호기·날짜 분포가 치우칠 수 있습니다.
- 원본 폴더에는 **정상(결함 없음) 이미지가 없습니다.** 모두 NG 판정 이미지이므로, 이미지 단위 오검출(FP) 평가에는 별도 정상 데이터가 필요합니다. NG 판정 이미지 중에도 실제 결함이 없는 경우(장비의 오판)가 있을 수 있으나 확인하지 않았습니다.
- 라벨링 세트 간 포함 관계는 위 "서브셋 포함 관계"에서 확인했습니다. 다만 각 `last*.pt` 가중치가 어떤 분할로 학습되었는지는 알 수 없어, 이 가중치로 시작한 학습의 평가는 누수 가능성이 있습니다.
- 대회 공식 데이터(약 1.8GB)와 이 로컬 데이터의 관계는 확인되지 않았습니다.
- `train.txt`/`test.txt`는 노트북 실행 때마다 재생성되므로 평가 재현이 필요하면 `seed`를 고정하거나 파일을 보관하세요.

## 6. 학습용 분할 (`data/splits/`)

`scripts/make_split.py`가 `n400`을 **실제 호기별로 층화하고 촬영 묶음 단위로 train/val/test = 8:1:1**로 나눕니다(seed 42, 호기는 `data/manifest.csv`의 `unit`).

- **묶음**: 같은 호기에서 60초 이내로 연속 촬영된 이미지는 같은 분할에 넣습니다(촬영 간격 중앙값이 4초라 연속 촬영본이 많음). 400장이 95묶음(1호기 22 / 2호기 20 / 3호기 53)이 되었습니다.
- **층화**: 호기마다 따로 8:1:1로 나눠 모든 분할에 세 호기가 들어가고, 호기 내 이미지 수·bbox 수 비율이 목표에 가깝게 각 호기에서 2만 번 무작위 배정 중 최선을 골랐습니다.
- **검증**: 분할 간 겹치는 이미지 0개. 서로 다른 분할에 속한 같은 호기의 인접 이미지 간 최소 촬영 간격은 13,204초(약 3.7시간)로 60초 기준 누수 후보가 없습니다.

| 분할 | 이미지 | bbox | 이미지당 bbox | 이미지 (1호기 / 2호기 / 3호기) | bbox (1호기 / 2호기 / 3호기) | 촬영 날짜 수 |
|---|---|---|---|---|---|---|
| train | 320 | 832 | 2.60 | 99 / 87 / 134 | 297 / 243 / 292 | 19 |
| val | 38 | 104 | 2.74 | 12 / 10 / 16 | 36 / 30 / 38 | 5 |
| test | 42 | 111 | 2.64 | 13 / 12 / 17 | 39 / 35 / 37 | 8 |

- 산출물: `split.csv`(이미지별 분할), `train/val/test.txt`(이 PC의 절대경로, 스크립트가 재생성), `val.data`, `test.data`
- 재현: `python scripts/build_manifest.py`(원본 폴더 필요) → `python scripts/make_split.py`

### 이전 분할(파일명 접두 기준)과의 관계

처음 만든 분할은 호기가 아닌 파일명 접두(001/002)로 묶어 1·2호기가 섞였고 호기 균형이 나빴습니다(val 이미지 호기별 10 / 5 / 25, bbox 60개, 이미지당 bbox 1.5). 해당 분할로 시작한 실험 2건(SPP 12 epoch 근처, tiny 초기)은 재분할과 함께 중단했고 기록용으로 `outputs/runs/_aborted_oldsplit_*`에 남겼습니다. 옛 분할표는 `data/splits_old_prefix/split.csv`입니다. **이전 분할의 어떤 수치도 새 분할과 비교하지 않습니다.**

### 한계

- val 38장(bbox 104), test 42장(bbox 111)으로 이전보다 늘었지만 여전히 작아 F1이 몇 개 차이로 흔들립니다. 최종 비교는 묶음 기준 교차검증을 권장합니다.
- val은 촬영 날짜가 5일, test는 8일뿐이라 날짜(시기) 다양성이 낮습니다. 묶음 단위로 나눈 결과입니다.
- 묶음이 큰 호기가 있어(예: 12장짜리 묶음) train의 실질 다양성은 320장보다 적습니다.
