# 추가 분석 정리 (호기·해상도, 오경보, 점 합성, 속도)

모델 3종(Faster R-CNN R50-FPN, YOLOv3-tiny, Faster R-CNN MobileNetV3-FPN)의 **오류·강건성·조건별 분석** 결과와 해석. 숫자 표는 [experiments.md](experiments.md), 평가 규칙은 [README.md](README.md), 점 제거 실험 해석은 README의 "점 제거 실험" 절에 있다.
- 마지막 갱신: 2026-10-07 (브랜치 `feat/minyeop-normal-false-alarm`)
- 아래 모든 수치는 test 396장(정답 663개) 기준이고, 임계값은 모델별로 val에서 정해 고정한 값(R50 0.95 / YOLOv3-tiny 0.06 / MobileNet 0.93)이다. **강건성 시험은 test 이미지로 먼저 수행했다** (6절 참고).

## 0. 핵심 결론
1. **호기·해상도에 따른 뚜렷한 성능 차이는 확인되지 않는다.** 가장 낮은 그룹(1호기·352x332)은 공식 라벨 박스가 76%라서 IoU 점수가 낮은 것이고, 중심 거리 기준(평가 v2)에서는 거의 모든 그룹이 만점이다.
2. **점을 지우면 검출이 거의 사라진다.** 모델은 결함의 점 자체를 단서로 쓴다 (상세는 README의 점 제거 실험).
3. **가짜 정상 이미지의 오경보는 만드는 방식에 따라 0~64%로 달라진다.** 평균 보간에서는 세 모델 모두 0.8% 이하, 노이즈를 더한 보간에서는 YOLOv3-tiny와 MobileNet이 크게 흔들리고 R50만 0.5% 이하로 안정적이다.
4. **MobileNet은 점이 평소 위치가 아닌 곳에 있으면 거의 못 찾는다.** 실제 세기의 점을 무작위 자리에 넣으면 R50·YOLO는 약 89~90%, MobileNet은 30%다.
5. **옅은 점(대비 약 13 미만)은 R50·YOLO도 많이 놓친다.** 현재 test의 실제 점은 거의 이보다 진해서(하위 10%가 대비 약 17) 놓침이 없었을 뿐이다.
6. **속도는 YOLOv3-tiny > MobileNet > R50.** CPU에서 R50은 장당 0.6~2초다. 촬영 간격이 약 4초라 세 모델 모두 처리량은 문제가 아니다.
7. 위 합성·제거 시험은 모두 **인위적으로 만든 이미지**를 쓰므로 실제 현장 성능이 아니라 모델 간 상대 비교와 취약점 탐색으로 해석한다.

## 1. 호기·해상도별 통계
- **방법**: `manifest.csv`의 호기·해상도와 `preds_test.json`을 이미지 이름으로 합쳐 그룹별 F1, mAP50-95, FN, 평가 v2 결과를 계산 (코드 `src/minyeop/group_stats/group_stats.py`, 그림 `figures.py`).
- **결과**: 표는 experiments.md "호기·해상도별 결과". 그림은 `runs/minyeop/07_group_stats_v1/figures/group_chart_test.png`, `group_samples_test.png`.
  - 세 모델 모두 1호기·352x332가 가장 낮다 (mAP50-95: R50 0.411, YOLO 0.389, MobileNet 0.373 / 전체 0.611, 0.558, 0.559).
  - 평가 v2(중심 5px)에서 R50과 YOLOv3-tiny는 **모든 그룹 FN 0 / FP 0**, MobileNet만 1호기·352x332에서 FN 1, 3호기에서 FP 1.
- **교란**: 해상도별 공식 라벨 박스 비율이 크게 다르다 (1호기·316x332 10%, **1호기·352x332 76%**, 2호기 23%, 3호기 17%). 공식 라벨은 박스 크기가 제각각이라 IoU 점수가 낮아진다.
  - 공식 라벨 이미지만 비교하면 해상도별 F1이 0.956~0.977(R50)로 좁아지고 구간이 겹친다 (예: 576x444 재현율 0.882~0.996, 352x332는 0.891~0.983).
- **한계**
  - 공식 라벨 이미지는 호기별 20~36장, 해상도 412x332는 정답 박스가 2개뿐 → 그룹별 비교는 표본이 작다
  - 해상도가 호기와 겹치는 축이라(1호기에 3종, 2호기 316x332는 1호기와 같은 해상도) 순수한 호기 효과와 해상도 효과를 분리하지 못한다
  - 맞힌 검출의 중심 오차(중앙값)는 YOLOv3-tiny·MobileNet에서 3호기(576x444)가 가장 크고(0.83, 0.85px, 다른 호기 0.65~0.74px), R50은 1호기와 3호기가 같다(0.70px, 2호기 0.60px). 픽셀 해상도 효과일 수 있으나 확인하지 못했다
- **보고서 문구 제안**: "호기·해상도별로 뚜렷한 성능 차는 없었다. 1호기·352x332의 낮은 IoU 점수는 해당 그룹의 공식 라벨(박스 크기 불균일) 비율이 높은 영향이며, 중심 거리 기준에서는 모든 그룹에서 검출되었다."

## 2. 가짜 정상 이미지 오경보
- **목적**: 데이터에 정상 제품 이미지가 사실상 없어서(빈 라벨 105장은 제품이 반만 찍힌 특수한 사진), test 결함 369장의 점을 지운 이미지를 "가짜 정상"으로 보고 이미지 단위 오경보를 잰다. 같은 사진의 결함 있음/없음 쌍이 생긴다.
- **방법**: 점 제거 코드를 재사용(평균 보간 / Navier-Stokes+노이즈 × 13x13 / 17x17). 코드 `src/minyeop/fake_normal/false_alarm.py`, 결과 `runs/minyeop/05_fake_normal_v1/` (`summary.json`, `per_image.csv`).
- **결과** (표는 experiments.md)
  - 평균 보간: R50 0~0.5%, YOLO 0.3~0.8%, MobileNet 0.3~0.8%
  - Navier-Stokes+노이즈: R50 0.3~0.5%, **YOLO 22.2~38.5%, MobileNet 33.6~64.0%**
  - 노이즈 보간의 오경보는 거의 전부 점을 지운 바로 그 자리다 (MobileNet 13x13에서 395건 중 391건, YOLO 219건 중 215건). 노이즈 무늬가 점처럼 보여 반응한 것
  - 이미지 점수로 본 결함 있음/없음 구분력(ROC-AUC)은 R50이 모든 설정에서 약 1.000, MobileNet은 노이즈 13x13에서 0.842
  - 빈 라벨 27장의 오경보는 전부 0장
- **해석**: 노이즈 무늬에 대한 강건성이 R50과 나머지 두 모델을 가르는 몇 안 되는 지표다 (mAP50-95에서 R50이 앞선 것과 같은 방향).
- **한계 (중요)**
  - 가짜 정상은 점만 지운 이미지이지 진짜 정상 제품이 아니다. 평균 보간(평평한 패치)은 모델이 쉽게 "없음"으로 판정하는 쉬운 조건일 수 있고, 노이즈 보간은 무늬 자체가 헛경보를 일으키는 어려운 조건일 수 있다. **실제 정상 제품의 오경보율은 이 두 값 사이 어딘가이고 어디인지는 이 실험으로 알 수 없다.** 보고서에는 단일 값이 아니라 범위로 쓸 것
  - 시드 하나, 임계값은 이미지 단위 오경보를 줄이는 기준이 아니라 IoU 기준 val F1 최대값

### 2-2. 점 제거·가짜 정상, 6개 모델 (팀원 모델 포함)
- **방법**: 2절·점 제거와 같은 설정(평균 보간 4/6/8, 평균+노이즈 6, NS+노이즈 4/5/6/8, 시드 0)으로 6개 모델을 다시 돌렸다. 두 분석이 같은 이미지라 한 번에 계산한다. 기존 R50·YOLOv3-tiny 숫자가 그대로 재현되어 새 모델 결과도 같은 기준이다.
- **점 자체가 단서다 (6개 모델 공통)**: 노이즈 없는 평균 보간으로 반변 6px 이상 지우면 남는 검출이 663개 중 0~3개다. 점이 사라지면 검출도 사라진다(결함의 정체는 점이다).
- **노이즈를 더한 보간에 대한 반응은 모델마다 크게 다르다**:
  - 거의 반응 없음: R50(0.3~0.5%), YOLO26n(0.8~4.1%).
  - 크게 반응: MobileNetV3(34~64%), D-FINE(20~49%), YOLOv3-tiny(22~39%), RT-DETR(20~37%). 오경보 대부분이 **지운 자리**에서 나온다(예: NS+노이즈 6에서 YOLOv3-tiny 215개 중 지운 자리 215, MobileNet 391/395). 모델이 점의 형태 말고 "작은 어두운 얼룩 질감"에도 반응한다는 뜻이다.
  - 오경보율은 임계값에 좌우되므로 **AUC(원본 대 가짜 정상)**를 함께 본다. 지운 자리가 원본 점과 가장 구분이 안 되는 모델은 MobileNet(0.842)과 D-FINE(0.900)이고, YOLOv3-tiny(0.997)와 RT-DETR(0.974)은 구분은 되지만 임계값이 낮아(YOLOv3-tiny 0.06) 오경보가 많이 나온다. 이전 문서의 "YOLO 22~39%"는 상당 부분 낮은 임계값 탓이다.
- **D-FINE은 노이즈 없는 평균 보간에서도 오경보가 가장 많다**(4.1%, 2.4%). 대부분 지운 자리 밖이다(15개 중 14개, 9개 중 9개). 느슨한 임계값(0.66)과 DETR 계열의 배경 오검출 성향이 의심되나 확인하지 않았다.
- **한계**: 가짜 정상은 진짜 정상이 아니다. R50과 YOLO26n이 반응하지 않는 것이 진짜 강건성인지, 보간·노이즈 패턴을 못 보는 것인지는 가려내지 못했다. 보간 흔적의 영향은 모델마다 다를 수 있다. test 이미지 기반이며(6절), 빈 라벨 27장은 오경보가 0이지만 제품이 반만 찍힌 특수 사진이다.
- **시사점(제안)**: 현장 오경보 관점에서는 R50·YOLO26n이 유리하다. 단 YOLO26n은 합성 점의 3호기에서 약했다(3-3절). 오경보에 약한 모델은 임계값을 높이는 대신 옅은 점을 놓칠 수 있다(트레이드오프).

## 3. 점 합성 시험 (미탐지 조건 분석)
- **목적**: 실제로는 놓침이 거의 없어서 분석할 미탐 사례가 없으므로, 옅은 점을 만들어 어디서부터 놓치는지 본다.
- **방법** (코드 `src/minyeop/synth_insert/insert_dots.py`, 결과 `runs/minyeop/06_synth_insert_v1/`)
  - 바탕: test 이미지의 점을 평균 보간(13x13)으로 지운 이미지
  - 점 은행: **val의 실제 점** 606개에서 둘레 밝기로 나눈 투과율 조각(9x9)을 만들고, 같은 호기의 조각에 `T^s`(s = 깊이 배율)를 곱해 넣음. 크기 배율 f(0.67, 1.0, 1.5)는 조각을 다시 그림
  - 자리 두 가지: 원래 점이 있던 자리(663개), 제품 안 무작위 자리(1,107개). 같은 자리·같은 조각을 모든 (s, f) 칸에서 사용
  - 판정: 모델 임계값 이상 검출의 중심이 넣은 점에서 5px 이내
- **결과** (표는 experiments.md "점 합성 시험", "측정 대비별")
  - 실제와 같은 세기·크기(s=1.0, f=1.0): 원래 자리 / 무작위 자리 = R50 90.2 / 89.4, YOLO 91.1 / 89.5, **MobileNet 97.1 / 30.4** (3호기 무작위 자리는 2%)
  - 측정 대비가 9~13이면 원래 자리 검출률이 R50 72%, MobileNet 73%, YOLO 36%, 13~18에서 각각 89%, 92%, 75%. 무작위 자리에서는 R50이 25 이상에서야 87%
  - 합성 점이 있는 이미지에서 점 자리 밖 오경보는 이미지의 1.4~3.8%
- **해석**
  - MobileNet은 점이 뚜렷해도 평소 위치가 아니면 못 찾는다 → **위치(맥락) 의존.** test F1 0.986이 이 의존 덕분일 수 있다
  - R50·YOLO는 강한 점에서는 자리와 무관하지만, 옅어질수록 원래 자리가 유리하다 (같은 대비에서 원래 자리 > 무작위 자리)
- **한계 (중요)**
  - **합성 점에 사각형 자국이 보인다.** 점은행 조각(9x9)에 점 주변의 어두운 틀이 포함되어 무작위 자리에서 점 없는 회색 사각형처럼 보이는 경우가 있고, 원래 자리에는 내가 지운 13x13 평탄 패치의 틀이 남는다. 그래서 "원래 자리 > 무작위 자리" 차이를 자리 효과로만 단정할 수 없다
  - 합성 점은 실제보다 약 10%p 덜 현실적이다 (실제 점은 100% 검출, 합성 s=1.0은 R50 90%). 절대 검출률이 아니라 모델 간 상대 비교로만 쓸 것
  - 아무것도 넣지 않은 대조군(s=0)이 이 격자에는 없다
- **제안 (2차 실험, 미실시)**: 원래 자리는 점을 지우지 않고 **실제 점의 깊이만 비율로 옅게**, 무작위 자리는 **헤일로를 뺀 점만** 넣고, s=0 대조군 포함

### 3-2. 막대 안 합성 점 평가 (`scripts/synth_eval.py`, 2차)
- **방법**: 실제 점을 평균 보간으로 지우고, 영상에서 찾은 **작대기(막대) 안쪽**에만 val의 실제 점(투과율 조각)을 s(진하기) x f(크기) 12칸으로 합성했다. 시드 42, 이미지 386장·점 1,436개, 팀원 PC에서 `--verify`로 같은 데이터인지 확인한다. 1차(3절)와 달리 점을 지우지 않은 원래 자리가 없고, 막대 밖에는 놓지 않는다.
- **결과**(`experiments.md` 표):
  - 대비가 낮을수록 놓친다. 대비 6 미만은 세 모델 모두 거의 0%, 20 이상에서 R50·YOLO 약 82%. 1차의 "대비 약 13 미만이면 놓침"과 같은 방향이다.
  - 실제 세기·크기(s=1.0, f=1.0)에서 R50 80~95%, YOLO 83~97%. 실제 점은 test에서 100% 찾으므로 합성과 약 10%p 차이가 있다는 1차 결론이 유지된다.
  - **MobileNetV3는 전 구간에서 낮고, 3호기에서 거의 못 찾는다.** 실제 세기·크기에서 3호기 2.4%(R50·YOLO 95%), 대비 14 이상으로 맞춰도 4.2%(R50 75%, YOLO 70%). 1·2호기는 76%·56%이다. 대비를 맞춘 비교라 합성 점이 3호기에서 옅게 만들어진 탓이 아니다.
  - 오경보는 세 모델 모두 4~13개(FPPI 0.034 이하)로 적다. 합성 점에서 R=2px 검출률이 R=5px보다 크게 낮은 것은 MobileNet(12.6% → 6.5%)뿐이라 박스 위치 정밀도도 낮다.
- **해석 (가설, 검증 안 함)**: 같은 MobileNet이 실제 3호기 점은 찾는데(호기별 통계에서 3호기 약점 없음) 합성 3호기 점은 못 찾는다. 실제 점에만 있는 단서(예: 표시 제거 흔적)를 쓰거나, 합성 점의 모양(3호기 13px 박스·해상도 576x444)이 stride 16 이상만 쓰는 MobileNet FPN에 불리할 수 있다. 어느 쪽인지는 가려내지 못했다. 이전의 "무작위 자리 30%"와 일관된다.
- **한계**: 합성 점의 사각 흔적과 실제와의 약 10%p 차이는 그대로다. 막대 검출은 실제 점 663개 전부가 검출된 막대에 닿는지로만 검증했고 사람이 그린 정답은 없다. s=0.15·0.3 칸의 점은 대부분 대비 10 미만이라 실제 결함 범위 밖일 수 있는데, 실제 점의 대비 분포와는 비교하지 않았다. s=0 대조군은 없다.
- **test 사용**: 이 시험도 test 이미지가 바탕이다(6절).

### 3-3. 6개 모델 비교 (팀원 모델 포함)
- **방법**: `weights/pts/`의 가중치(우리 3 + YOLO26n·RT-DETR-l·D-FINE-N)를 같은 코드로 실제 val·test와 합성 데이터(3-2절)에 돌렸다. 팀원 모델은 만든 사람의 설정(YOLO26n 입력 1024·최대 검출 50, RT-DETR 640·300, D-FINE 640 직접 리사이즈·정규화 없음)을 따랐다. 임계값은 모델마다 val에서 F1 최대인 값.
- **실제 test는 모두 포화**: F1 0.986~0.991, v2(R=5) 0.998~1.000. 구분은 박스 정밀도(mAP50-95)에서만 되고 D-FINE 0.659 > RT-DETR 0.639 > YOLO26n 0.633 > R50 0.611 > MobileNet 0.559 ≈ YOLOv3-tiny 0.558 순이다. 이 순서는 박스 정밀도이지 찾는 능력이 아니다(팀 라벨 고정 크기 영향 주의).
- **합성 점, 모델마다 val 임계값**: D-FINE이 가장 많이 찾는다(전체 49.8%, 대비 14~20에서 87%). 그러나 이 우위는 대부분 **임계값 효과**다. D-FINE의 val 임계값(0.66)은 R50(0.95)보다 느슨해 오경보도 많다(24개 대 13개).
- **합성 점, 임계값과 무관한 비교**: 합성 점 AP는 D-FINE 0.574 ≈ R50 0.567 > YOLOv3-tiny 0.515 ≈ YOLO26n 0.501 > RT-DETR 0.451 >> MobileNet 0.262. 오경보를 이미지당 0.03 이하로 맞추면 다섯 모델이 33~39%로 붙고(차이가 신뢰구간 안), MobileNet만 16%로 뒤처진다. 즉 **옅은 점을 찾는 능력은 MobileNet을 빼면 모델 간 차이가 작다.**
- **호기별(대비 14 이상)**: MobileNet만 3호기에서 거의 못 찾는 것이 아니다. YOLO26n·RT-DETR도 3호기가 61%로 1·2호기(73~81%)보다 낮다. R50·YOLOv3-tiny·D-FINE은 호기 차이가 작다(D-FINE 3호기 89%). 3호기 합성 점의 약점이 모델 일부에 퍼져 있지만 원인은 검증하지 못했다(합성 점의 3호기 해상도·박스 크기와의 상호작용, 실제 점에만 있는 단서 등). n=212라 구간이 약 ±6%p다.
- **한계**: 오경보 예산별 검출률의 임계값은 합성 이미지 자체로 골랐다(비교 분석용이며 모델 선정이 아님). FPPI 0.01 예산은 오경보 4개 수준이라 불안정해 표에서 뺐다. 팀원 모델의 임계값은 이 문서 규칙으로 다시 골랐다. 합성 점과 test 사용에 대한 한계는 3-2절과 6절과 같다.
- **가중치 폴더 주의**: `weights/pts/faster r-cnn mobilenetv3/best.pt`는 MobileNet이 아니라 **R50**(우리 `01_…/weights/best.pt`와 md5 동일)이고 MobileNet은 `best(1).pt`다. `faster r-cnn resnet50/`는 비어 있다. `yolov3-tiny/best.pt`는 우리 `02_…/weights/best.pt`와 같다. 폴더 이름을 바로잡거나 README에 적어 둘 것.

## 4. 추론 속도
- **방법**: 이미지 1장씩(배치 1), 연산 동기화, 디스크 읽기 제외, 모델 연산과 후처리(NMS 등) 포함. GPU RTX 4050 Laptop(200장), CPU Intel Core i7-13620H(30장, 스레드 1·4·8·16). 표는 experiments.md "추론 속도"
- **결과**: GPU 4.8ms(YOLO) / 11.3ms(MobileNet) / 48.4ms(R50). CPU 16스레드 35 / 73 / 584ms, 1스레드 142 / 149 / 2,073ms
- **촬영 간격**: `manifest.csv`의 같은 촬영 묶음 안 연속 촬영 간격은 호기와 관계없이 **중앙값 4초**(5% 분위 3초). 촬영 간격이지 검사 사이클 요구는 아니지만 대략의 상한으로 보면, CPU 1스레드의 R50(2.1초)도 간신히 따라가고 나머지는 여유가 크다
- **한계**
  - 측정은 1회이고 CPU 값은 실행마다 20~40% 변동했다 (16스레드 재측정: YOLO 56→35ms, MobileNet 115→73ms, R50 733→584ms). 범위로 쓸 것
  - AMP는 배치 1에서 오히려 느리고 변동이 컸다(R50 48→65ms, p95 153ms). 원인 미확인이라 보고서에는 fp32 값을 쓸 것
  - YOLO의 640 리사이즈는 시간에서 빠지고 Faster R-CNN은 내부 리사이즈가 포함되어 YOLO가 수 ms 이하로 유리하다
  - **공장 장비의 실제 CPU 사양은 알지 못한다.** 스레드 수는 1·4를 함께 보고하는 것이 안전하다
  - 파라미터 수는 2클래스로 바꾼 우리 모델 기준(R50 41.4M, MobileNet 19.0M, YOLOv3-tiny 8.7M)이고, 이전에 문서에 적은 41.8M / 19.4M은 COCO 91클래스 헤드 기준이라 정정했다

## 5. 모델 선정 기준 (제안)
선정은 **val 성능으로만** 하고 결과를 본 뒤 기준을 바꾸지 않는다.
1. val mAP50-95 (공식 라벨 포함): R50 0.615 / MobileNet 0.583 / YOLOv3-tiny 0.579 (공식 라벨만 0.337 / 0.322 / 0.311)
2. 동률이면 강건성(오경보, 점 제거, 점 합성 — **val 이미지로 재수행 필요**)
3. 그다음 속도·크기
- 현재 신호는 모두 R50을 가리킨다 (val·test mAP50-95, 노이즈 오경보, 위치 강건성). "best"를 하나로 말하기보다 **정확도 최우선: R50 / 경량 대안: YOLOv3-tiny**로 목적별로 쓰는 것을 권한다. MobileNet은 위치 의존 때문에 권하지 않는다.

## 6. test 사용 이력 (보고서에 숨기지 말고 적을 것)
- 강건성 시험(점 제거, 가짜 정상, 점 합성 1·2차, 호기·해상도 통계)은 **test 이미지로 먼저 수행**했다. test 점수는 이미 한 번씩 확인된 상태다.
- 이 결과를 최종 모델 선정 근거로 쓰려면 같은 시험을 **val 이미지로 반복**해야 한다 (점 합성은 점은행을 val 대신 train에서 가져와야 함). 스크립트에 `--split val` 옵션 추가 필요, 예상 소요 30~40분.
- 반복하지 않는다면 보고서에는 "강건성 시험은 선정 후 분석용(test 이미지)이며 선정 근거는 val 성능"이라고 명시한다.
