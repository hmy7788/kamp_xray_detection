# 데이터 계보 (기록용, 실행하지 않는다)

`data/images/` 의 사진은 KAMP 원본(BMP, 5,360개)에서 아래 순서로 만들었다 (2026-10-02). 이 폴더의 스크립트가 그 과정이다.
지금의 데이터는 확정본이라 다시 만들지 않는다. 보고서의 "전처리" 설명에 쓴다.

1. `build_manifest.py`: 원본을 훑어 중복(내용 해시 같은 파일 277쌍) 제거, 장비(폴더 N호기)·촬영 시각(파일명)·묶음(burst, 같은 장비 60초 이내) 기록.
2. `preprocess.py fill` (v1_fill): 장비가 그려 넣은 색상 박스 픽셀(채도 > 0)을 주변 회색 픽셀 평균으로 메움(커널 5). 회색조 PNG 로 저장.
   - 왜: 공식 라벨 중심의 99.8% 가 색상 박스 안에 있어, 지우지 않으면 모델이 "색 네모 찾기"를 배운다 (docs/decisions/001).
   - 비교 후보였던 v0_raw(안 지움)·v2_inpaint(OpenCV 인페인팅)·v3_mask(단색 덮기)는 쓰지 않는다.
3. `check_data_version.py`: 사진 수·크기·라벨 짝·색 픽셀 0개 검사.
4. `eda_raw.py`: 원본 진단. 결과는 docs/history/eda_raw_2026-10-02.md.

라벨 없는 2,032장의 라벨은 팀이 직접 찍었다 (Label Studio, 클릭 → 공식 라벨 중앙값 크기의 네모). docs/contracts/data.md 참고.
